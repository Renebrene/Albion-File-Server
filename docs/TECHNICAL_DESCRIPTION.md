# Техническое описание проекта «АЛЬБИОН — файловый сервер»

## 1. Назначение

«АЛЬБИОН» — self-hosted файловый сервер для хранения и обмена файлами через браузер. Администратор управляет хранилищем в веб-проводнике, загружает и перемещает файлы, создаёт папки и формирует экспорты. Для пользователей и автоматизированных клиентов предусмотрены прямые публичные ссылки на файлы, страницы публикации папок, временные ссылки на ZIP-архивы и HTTP API.

Административный интерфейс защищён логином, паролем и CSRF-токеном. Публичные ссылки являются bearer-ссылками: отдельная авторизация при открытии файла не требуется, поэтому доступ к такой ссылке означает доступ к её содержимому.

## 2. Основные функции

### Веб-проводник администратора

- Просмотр файлов в табличном, плиточном и списочном режимах.
- Навигация по папкам и хлебным крошкам.
- Создание и удаление папок; загрузка одиночных файлов, нескольких файлов и структуры папок.
- Переименование, перемещение, настройка короткого URL и удаление файлов.
- Групповые операции с выбранными элементами.
- Drag-and-drop загрузка и перемещение файлов между папками.
- Просмотр размера, даты, числа файлов и рекурсивной статистики папок.
- Фильтры, сортировка и пагинация на сервере; состояние отражено в URL. Удаление и перемещение обновляют строки без перезагрузки страницы, сохраняя выделение и очередь загрузки.
- Адаптивная вёрстка: на узких экранах таблица переходит в карточки. Интерфейс проходим с клавиатуры (фокус-кольца, модалки с Tab/Escape и возвратом фокуса, `aria-label` у иконочных кнопок).

### Публикация и экспорт

- Публичное скачивание файла по физическому пути, короткому транслитерированному адресу или пользовательскому алиасу.
- Публичная страница папки `/d/<slug>` показывает только файлы непосредственно в этой папке. Подпапки и родительская структура не раскрываются; для подпапки создаётся отдельная ссылка.
- Просмотр поддерживаемых изображений inline через `/v/<path>`.
- Создание XLSX-отчёта со списком файлов и ссылок.
- Создание ZIP по выбранным файлам/папкам. Для ZIP выдаётся публичная UUID-ссылка `/z/<uuid>`, действующая до 24 часов.
- Полный ZIP-экспорт через `/export_all` с ограничением доступа, часовой квотой и бюджетом скачивания.

### Автоматизация и наблюдаемость

- API-токены для автоматизированных скачиваний и загрузки. Ключ передаётся заголовком `X-API-Key`; в БД хранится SHA-256-хеш, открытый ключ показывается только один раз. Токены выдаются в `/settings/tokens` или через `manage_tokens.py`, по умолчанию действуют 90 дней и имеют scopes `download`/`upload`/`delete`; write scopes обязательно привязаны к папке.
- Счётчики скачиваний и просмотров.
- Лог приложения `albion.log` с ротацией 5 МиБ × 3 файла.
- JSON-БД записываются атомарно; повреждённые файлы сохраняются как `.corrupt-*` для восстановления.

## 3. Архитектура и обработка запросов

```text
Браузер / API-клиент
        │ HTTPS
        ▼
Nginx (TLS termination, proxy, сетевые лимиты)
        │ localhost или внутренняя сеть
        ▼
Flask-приложение под Waitress (8 потоков, один процесс)
        ├── административный UI и HTTP API
        ├── публичные маршруты файлов, папок и архивов
        ├── Flask-Limiter и бюджеты скачивания
        └── JSON-метаданные и файловое хранилище
```

Основная логика, маршруты и HTML/CSS административного интерфейса находятся в `server.py`; клиентский код проводника — в `static/js/admin.js`. Файлы хранятся в файловой системе, а их метаданные, учётные данные, настройки и ключи — в JSON-файлах. Отдельная реляционная БД для одного процесса не требуется.

Приложение рассчитано на **один процесс Waitress с несколькими потоками**, а не на несколько WSGI workers или реплик. Внутрипроцессные блокировки защищают конкурентные изменения JSON, загрузки и создание ZIP, но не координируют несколько процессов.

## 4. Данные и файловая структура

Каталог данных задаётся `ALBION_DATA_DIR`. В production рекомендуется отдельный постоянный каталог, например `/srv/albion/data`; в Docker он монтируется в `/app/data`.

```text
ALBION_DATA_DIR/
├── uploads/          исходные загруженные файлы и каталоги
├── ziplinks/         временные ZIP по выборке
├── thumbnails/       кэш WebP-превью mini/medium (регенерируется автоматически)
├── files_db.json     метаданные файлов
├── folders_db.json   дерево папок и публичные slug
├── stats.json        служебные отметки статистики/экспорта
├── settings.json     настройки квот из админки
├── auth.json         имя администратора и хеш пароля
├── tokens.json       хеши API-ключей и их метаданные
├── .secret_key       ключ подписи Flask-сессий
└── albion.log        журнал приложения
```

Записи `files_db.json` связывают внутренний UUID с физическим относительным путём, папкой, отображаемым именем, короткой ссылкой/алиасом, размером, типом и счётчиками. `folders_db.json` содержит UUID папки, имя, родительскую папку и публичный slug.

Секретные JSON-файлы и ключ сессий создаются с правами `0600`. Резервные копии должны включать весь каталог данных. Рекомендуется хранить копию отдельно от сервера и регулярно проверять процедуру восстановления.

## 5. Аутентификация и модель доступа

- При отсутствии `auth.json` при первом старте создаётся bootstrap-учётная запись `admin / альбион`. Пароль хранится в виде хеша Werkzeug/scrypt. Перед публикацией сервера пароль необходимо сменить.
- Администратор входит через `/login`; сессия подписывается ключом `.secret_key`, имеет `SameSite=Lax`, срок жизни по умолчанию 12 часов и флаг `Secure` при `ALBION_COOKIE_SECURE=1`.
- Смена логина/пароля отзывает ранее выданные административные сессии. Это также действует при обновлении `auth.json` через `change_password.py`.
- Запросы, изменяющие данные (`POST`, `PUT`, `PATCH`, `DELETE`), требуют сессию и CSRF-токен. Браузерный UI отправляет его в заголовке `X-CSRF-Token`.
- Публичные файлы, публичные страницы папок и ссылки на созданные ZIP открываются без административной сессии.
- По умолчанию полный экспорт `/export_all` ограничен LAN-клиентами через явно доверенный reverse proxy, API-ключом или действующей сессией администратора. Настройку можно изменить из `/settings`.
- Для доверенных forwarded-заголовков используется `ALBION_TRUST_PROXY=1`, список адресов proxy задаётся `ALBION_TRUSTED_PROXY_IPS`. В примерах Nginx устанавливает XFF из `$remote_addr`. Backend нельзя делать доступным клиентам в обход доверенного прокси.
- Ответы включают `X-Frame-Options: DENY`, CSP `frame-ancestors 'none'`, `X-Content-Type-Options: nosniff` и `Referrer-Policy`. TLS/HSTS обеспечиваются reverse proxy.

## 6. Загрузка, квоты и ограничения

Допустимые расширения загрузки задаются в `server.py`: `txt`, `pdf`, `png`, `jpg`, `jpeg`, `gif`, `zip`, `rar`, `docx`, `xlsx`, `mp4`, `mkv`, `doc`, `xls`, `pptx`, `7z`. Проверка расширения — не антивирусная проверка содержимого и не гарантия безопасности файла.

Основные лимиты по умолчанию:

| Ограничение | Значение по умолчанию | Назначение |
|---|---:|---|
| Максимум одного запроса загрузки | 50 ГиБ | Ограничивает тело одного HTTP-запроса |
| Общая квота хранилища | отключена (`0`) | При задании ограничивает учтённый объём файлов |
| Минимальный свободный остаток диска | 5 ГиБ | Резерв свободного места для загрузок и ZIP |
| Размер исходных файлов для ZIP | 50 ГиБ | Ограничивает ZIP по выбранным файлам и полный экспорт |
| Число файлов в ZIP | 20 000 | Ограничивает количество файлов в архиве |
| Flask-Limiter | 100/час и 20/мин на внешний IP | Ограничение частоты запросов; локальные IPv4/loopback исключаются |
| Анонимный бюджет скачиваний | 10 ГиБ/час/IP | Ограничивает общий объём скачивания |
| Бюджет API-ключа | 100 ГиБ/сутки/ключ | Ограничивает общий объём скачивания по ключу |
| Полный ZIP `/export_all` | 1 раз/час на IP или ключ | Дополнительная квота полного экспорта |

Квоты загрузки и ZIP редактируются администратором в `/settings`, сохраняются в `settings.json` и применяются без перезапуска. Значения environment используются как значения по умолчанию, пока настройки ещё не сохранены.

Папочная загрузка выполняется браузером пакетами по 25 файлов, максимум 4 параллельных XHR-запроса. Структура каталогов сохраняется по относительному пути браузера. Для multipart-загрузок с активными квотами требуется известный `Content-Length`; ошибки квот возвращаются как HTTP `411`, `413`, `429` или `507` в зависимости от причины.

Проверка места для обоих ZIP-маршрутов и создание архивов сериализованы `ZIP_BUILD_LOCK` внутри одного процесса. Это не межпроцессная блокировка и не полноценное резервирование диска от других процессов/загрузок.

## 7. Интерфейсы и основные маршруты

Полная таблица API, схемы параметров и примеры находятся в [`API.md`](API.md). Основные группы маршрутов:

- Админка: `/login`, `/logout`, `/f/`, `/f/<folder_id>`, `/settings`.
- Публичный обмен: `/<slug-or-path>`, `/v/<path>`, `/d/<folder_slug>`, `/z/<uuid>`.
- Загрузка и управление: `/upload`, `/upload_folder`, `/api/create_folder`, `/api/update_file`, `/api/move_file`, `/api/move_files_batch`, `/api/delete_file`, `/api/delete_files_batch`, `/api/delete_folder`.
- Экспорты: `/export_xlsx`, `/api/export_zip`, `/export_all`.
- Автоматизация: API-ключ в `X-API-Key` для скачивания файла или `/export_all`.

## 8. Технические требования

### Требования к программной среде

- Linux-сервер; в контейнерном варианте — Docker Engine и Docker Compose.
- Python **3.12** для нативного запуска. Docker-образ основан на `python:3.12-slim`.
- Python-пакеты фиксированных/ограниченных версий указаны в `requirements.txt`: Flask 3.1.3, Waitress 3.0.2, Flask-Limiter 4.1.1, Werkzeug 3.1.8, openpyxl 3.1.5 и зависимости.
- Nginx рекомендуется для TLS termination, reverse proxy и ограничения сетевых соединений. Waitress напрямую в интернет не публиковать.
- Постоянный каталог данных с правом чтения/записи для системного пользователя приложения. В Docker пользователь приложения имеет UID `10001`.
- Достаточный объём диска: размер набора файлов + временный объём ZIP (примерно до размера исходных файлов, поскольку архив использует `ZIP_STORED`) + резерв свободного места и запас на рост.

### Ресурсы сервера

Для заявленного масштаба (до примерно 5000 фотографий, единичные изменения в неделю и 1–2 скачивания в час) — практическая рекомендуемая, а не жёсткая минимальная конфигурация:

- **2 vCPU**;
- **4 ГиБ RAM**;
- SSD/NVMe; размер выбирать по фактическому объёму файлов и формуле выше. Ориентир для старта — около **200 ГБ под данные**, если набор фото и временные ZIP укладываются с резервом;
- 20–40 ГБ системного диска под ОС, код и журналы;
- сетевое подключение в соответствии с требуемой скоростью скачивания. Для небольшого офисного хранилища обычно достаточно 100 Мбит/с или выше.

GPU не требуется. При текущей нагрузке необязательны Redis и SQL. Отдельный backup-диск/сервер не входит в оценку рабочего диска и должен планироваться отдельно.

## 9. Развёртывание

Поддерживаются два описанных варианта:

1. **Нативный Linux:** systemd запускает Waitress на `127.0.0.1:5000`, Nginx принимает HTTPS и проксирует запросы. Снаружи открыты только 80/443 (или только 443, если не нужен HTTP challenge/redirect); порт 5000 закрыт firewall.
2. **Docker Compose:** контейнер приложения и контейнер Nginx; данные подключаются постоянным bind mount `./data:/app/data`; наружу опубликованы порты Nginx, но не порт приложения.

Для собственного домена задаётся `ALBION_BASE_URL=https://...`, настраиваются DNS/TLS и при доступе из офиса — split DNS или NAT loopback. Подробные инструкции и примеры: [`DEPLOYMENT.md`](DEPLOYMENT.md) и [`deploy/README.md`](../deploy/README.md).

## 10. Эксплуатационные ограничения

- JSON-хранилище рассчитано на один процесс Waitress. Несколько процессов/реплик, разделяющих один `ALBION_DATA_DIR`, могут конфликтовать; для масштабирования метаданные нужно переносить в SQLite/PostgreSQL с транзакциями.
- Redis — необязательное хранилище общих состояний лимитов/бюджетов для нескольких процессов; Redis не заменяет БД и транзакции метаданных. Без Redis такие состояния хранятся в памяти процесса и сбрасываются при перезапуске.
- Публичная ссылка не является ACL: её обладатель получает доступ к опубликованному содержимому. Контроль доступа сотрудников к сайту целесообразно дополнять VPN, firewall или IP allowlist на Nginx.
- Общая квота хранения по умолчанию выключена (`ALBION_STORAGE_QUOTA_GB=0`), поэтому её следует задать либо внимательно мониторить свободный диск.
- Тесты запускаются командой `python -m unittest discover -s tests -v` и используют временный `ALBION_DATA_DIR`; они не должны менять рабочие файлы.
