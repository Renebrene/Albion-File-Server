# АЛЬБИОН — файловый сервер

Flask-приложение для хранения и обмена файлами через веб-проводник. Публичные ссылки позволяют скачивать файлы и открывать папки; админка требует учётные данные и CSRF-токен. Есть автоматическое скачивание по коротким ссылкам/API-ключам, архивирование и XLSX-экспорт.

## Возможности

- Просмотр хранилища в таблице, плитке и списке; навигация по папкам и хлебные крошки.
- Загрузка файлов/папок, параллельные батчи, drag-and-drop в drop-zone и между папками.
- Создание/удаление папок, переименование файлов, алиасы, групповое перемещение и удаление.
- Короткие транслитерированные URL файлов и папок; публичные страницы папок.
- Счётчики скачиваний/просмотров, размер и рекурсивная статистика папок.
- Экспорт XLSX, ZIP по выбранным файлам/папкам, ZIP всего хранилища.
- API-ключи для автоматических загрузчиков и лимиты скачивания.
- Ротация `albion.log`, атомарные JSON-записи, резервные копии повреждённых JSON.

## Требования

- Python 3.12 (текущий production использует Python 3.12).
- Установленные зависимости из `requirements.txt`.
- Каталог данных, доступный пользователю приложения и имеющий достаточное свободное место.
- Для доступа из интернета: домен, HTTPS reverse proxy и firewall; не публикуйте Waitress напрямую.

## Быстрый запуск (Linux)

Из корня репозитория:

```bash
python3 -m venv venv
. venv/bin/activate
pip install -r requirements.txt
python change_password.py
python server.py
```

Если `auth.json` отсутствует при первом запуске, создаётся стартовая учётная запись **`admin` / `альбион`** (пароль хранится только как scrypt-хеш). Смените её в **`/settings`** перед публикацией сервера в интернет. `change_password.py` остаётся альтернативным способом смены пароля из терминала. Повреждённый `auth.json` не перезаписывается автоматически: вход будет закрыт.

По умолчанию Waitress слушает только `127.0.0.1:5000`. Для прямого доступа из LAN явно задайте `ALBION_HOST=0.0.0.0` и настройте firewall. За nginx включите `ALBION_TRUST_PROXY=1` только если backend недоступен клиентам напрямую; nginx должен перезаписывать XFF значением `$remote_addr`.

## Конфигурация через environment

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `ALBION_DATA_DIR` | `.` | Каталог `uploads/`, JSON-БД, ключей и логов |
| `ALBION_HOST` | `127.0.0.1` | Адрес Waitress; `0.0.0.0` включайте явно только при нужде в прямом LAN-доступе |
| `ALBION_TRUST_PROXY` | `0` | `1` доверяет одному hop только от peer IP из списка `ALBION_TRUSTED_PROXY_IPS`; включать только за закрытым backend |
| `ALBION_TRUSTED_PROXY_IPS` | `127.0.0.1,::1` | IP/CIDR прокси, от которых разрешено LAN-исключение `/export_all` при `ALBION_TRUST_PROXY=1` |
| `ALBION_PORT` | `5000` | Порт Waitress |
| `ALBION_BASE_URL` | `https://albion-rostov.cloudpub.ru` | Origin для создаваемых публичных ссылок; задайте свой HTTPS-домен |
| `ALBION_COOKIE_SECURE` | `0` | `1` включает Secure-флаг сессионной cookie; включать при HTTPS |
| `ALBION_SESSION_HOURS` | `12` | Максимальная длительность постоянной сессии |
| `ALBION_DL_BUDGET_GB` | `10` | Байтовый бюджет анонимного скачивания за час/IP |
| `ALBION_TOKEN_DL_BUDGET_GB` | `100` | Байтовый бюджет скачивания с API-ключом за сутки/ключ |
| `ALBION_MAX_UPLOAD_GB` | `50` | Максимальный размер одного HTTP-запроса загрузки; `0` — без Flask-лимита |
| `ALBION_STORAGE_QUOTA_GB` | `0` | Общая квота по учтённым файлам; `0` — без жёсткой квоты |
| `ALBION_MIN_FREE_GB` | `5` | Неприкосновенный резерв свободного диска для загрузок и ZIP |
| `ALBION_MAX_ZIP_GB` | `50` | Максимальный размер исходных файлов для ZIP (выделение и export_all) |
| `ALBION_MAX_ZIP_FILES` | `20000` | Максимум файлов в одном ZIP; `0` — без ограничения |
| `ALBION_EXPORT_ALL_INTERNAL_ONLY` | `1` | `/export_all` только из LAN за доверенным proxy, с API-ключом или действующей админ-сессией |
| `ALBION_REDIS_URL` | пусто | Redis для общих бюджетов скачивания и часовой квоты экспорта |
| `ALBION_RATE_LIMIT_STORAGE_URI` | `memory://` | Storage для Flask-Limiter; для нескольких процессов — `redis://...` |

Rate-limit Flask-Limiter по умолчанию хранится в памяти и сбрасывается при рестарте; для нескольких процессов задайте `ALBION_RATE_LIMIT_STORAGE_URI=redis://...`. Бюджеты скачивания и часовой `/export_all` также можно перевести на общий Redis через `ALBION_REDIS_URL`. Для Redis установите пакет `redis` (он включён в `requirements.txt`). Локальные адреса (loopback и RFC1918 IPv4) освобождены от request-rate limits, но байтовый бюджет скачивания применяется и к ним.

## Веб-интерфейс

1. Откройте `/login`, введите логин/пароль.
2. Навигация по хранилищу — ссылки на папки и хлебные крошки.
3. Файлы можно загружать выбором файлов, папки или перетаскиванием в область загрузки.
4. Файл можно перетащить на строку/плитку папки для перемещения.
5. Чекбоксы файлов/папок открывают панель групповых операций. ZIP формируется на сервере, ссылка `/z/<uuid>` публична в течение суток.
6. 🔗 у файла копирует короткий URL; 🔗 у папки копирует публичный `/d/<slug>` URL. Публичная страница папки показывает только её непосредственные файлы — родительские и дочерние папки по ссылке не раскрываются; для подпапки выдавайте отдельную ссылку.

Папочная загрузка отправляется группами по 25 файлов, максимум 4 XHR-потока. Путь `webkitRelativePath` сохраняет структуру директорий. Список различает одноимённые файлы из разных каталогов.

## API и данные

- Публичные скачивания и страницы `/d/` не требуют входа.
- Все административные POST/PUT/PATCH/DELETE требуют сессию и `X-CSRF-Token`.
- API-ключ для автоматического скачивания передаётся только заголовком `X-API-Key`.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты используют временный `ALBION_DATA_DIR`; рабочие `files_db.json`, `folders_db.json` и `uploads/` не изменяются. Последний QA-прогон включал backend unit/smoke-тесты и browser E2E-проверки на отдельном тестовом сервере.

## Важные эксплуатационные ограничения

- JSON-БД подходят одному процессу Waitress; межпроцессные блокировки не реализованы. Для нескольких workers/реплик используйте SQLite/PostgreSQL; Redis решает общий rate-limit/budget state, но не делает JSON-БД транзакционной.
- Без Redis бюджеты скачивания и время `/export_all` хранятся в памяти и сбрасываются при рестарте. С `ALBION_REDIS_URL` они общие для процессов, а при недоступности Redis автоматически используется memory fallback.
- Создание ZIP сериализуется `ZIP_BUILD_LOCK` внутри одного процесса; для нескольких процессов блокировка не общая.
- `ALBION_MAX_UPLOAD_GB` ограничивает один запрос (по умолчанию 50 ГиБ); `ALBION_MIN_FREE_GB` резервирует свободное место; `ALBION_STORAGE_QUOTA_GB` и `ALBION_MAX_ZIP_*` ограничивают общий объём и ZIP. Значение `0` отключает соответствующий лимит. Для браузерных multipart-загрузок требуется `Content-Length`.
- `/export_all` при настройке по умолчанию доступен LAN-клиентам через явно доверенный proxy, API-ключу или админ-сессии; ослабление ограничения в `/settings` делает его публичным в пределах часового лимита.
- Публичная ссылка — это возможность доступа к папке/файлу, а не полноценная ACL-модель. Любой, кто получил ссылку, может её открыть.

## Настройки квот в админке

После входа откройте **⚙️ Настройки** в шапке или `/settings`. Раздел доступен только администратору. Там задаются `max_upload_gb`, `storage_quota_gb`, `min_free_gb`, `max_zip_gb`, `max_zip_files` и режим «полный экспорт только из локальной сети/с API-ключом»; значения сохраняются в `settings.json` (права 0600) и применяются сразу, без перезапуска. Значения из environment используются только как defaults, пока файл настроек отсутствует; после сохранения приоритет у `settings.json`.
- Docker Compose и nginx-шаблон проверяются отдельно перед реальным запуском; не включайте их в production до проверки своего TLS/domain и разрешений bind volume.
